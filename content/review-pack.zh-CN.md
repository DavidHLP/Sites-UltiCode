# UltiCode 技术与机构评审包

更新于 2026 年 10 月 29 日。本文说明公开项目与网站当前的服务模式，是评审辅助材料，不是已签署的要约、认证、已完成的机构评估或生产验收报告。

## 产品与可用方式

UltiCode 是可自托管的在线评测平台，提供题目、练习提交、评测、比赛、题解、社区和管理功能。Console 是学习者界面；Management 是具有特权的运营界面。源码采用 MIT 许可，获取源码无需向本网站购买软件订阅；基础设施、人力与可选模型服务另行产生费用。

当前可用的评估模式是自托管：机构提供环境、运维人员与允许使用的评估数据。本网站不提供托管方案、付费试点名额、固定参与人数额度、支持响应时限或商业合同。

练习涵盖题目检索、题单、多面板做题工作台与提交结果。比赛提供报名、排名及适用场景下的虚拟参赛。学习者可查看自己的提交、题解与收藏；Management 提供题目和比赛管理、审核、审计与运维视图。这些是已实现工作流的说明，不代表目标部署已经通过端到端验收。

## 系统与数据边界

| 边界 | 当前实现参考 | 机构或运维方需要决定的内容 |
| --- | --- | --- |
| Auth | 凭据、OAuth、角色与浏览器会话；访问和刷新凭据使用 HttpOnly Cookie；刷新会话以哈希存储 | 身份提供方兼容性、账号生命周期、管理员开通与停用 |
| 五个 Owner | Auth、Admin、App、Submission 和 Notification 维持数据归属；Judge 与 Search 是独立 Worker | 地区、访问权、数据分级、运营凭据与迁移权限 |
| 执行 | Judge 消费提交任务并通过沙箱路径执行 | 运行限制、网络限制、补丁维护，以及启用 TLS 的生产远程或 rootless Docker |
| 存储与派生状态 | MySQL、兼容 S3 的对象存储、Redis 队列与可选 MeiliSearch 索引 | 存储位置、存储桶权限、备份覆盖、保留、删除与索引恢复 |
| Agent | 独立 Python 服务；对话和工作流状态独立于业务数据库及已保存学习计划 | 模型提供方、外部处理、允许的源码披露、持久化与费用政策 |

这些通用控制不代表已实现特定机构的 SAML、SCIM 或学习管理系统集成。自托管不等于合规认证。

## 当前 Agent 行为

实验性 Agent 默认关闭，缺失可用性设置时也保持关闭，必须由管理员显式启用。旧的 `VITE_AGENT_REVIEW_ENABLED` 前端标志不再被读取。功能设置不会启动独立 Python 服务、配置模型、授权外部调用或授予持久化权限。

符合条件的来源是账号本人的已完成普通练习提交，不包括比赛或尚未完成的提交。源码感知分析需要明确同意；源码读取上限为 12,000 个字符。打开工作区不会开始分析。模型调用与持久化具有独立运行控制。

本地回环开发可在没有共享累计预算政策的情况下启用真实调用，同时保留单次请求限制。运维方必须考虑真实提供方费用；单次运行限制不能形成总支出上限。非回环部署要求文档规定的有效预算政策。本网站不会发起模型调用。

面向学习者启用前，请审查提供方处理地区、允许披露的源码及保留政策。对话历史保留至所有者删除，已保存学习计划具有独立生命周期。取消分析不会清除历史，也不会撤销已完成的业务写入。

## 部署与恢复

生成配置前先选择安装路径。使用已发布镜像时，遵循选定发行版的 Operations 安装入口及其资产、签名、TLS/Judge 和批准要求。全新本地开发应在 `.env` 尚不存在时从 Development 空卷入口开始，不要先运行 `init-env.sh`。已有配置、数据库或卷时应保留数据并进入升级/回滚流程；不要用 `--force` 重建配置，也不要用修改标记替代迁移。参见 {{ORIGIN}}/get-started/ 及固定版本的 Operations/Development 指南。

请使用仓库生命周期入口。文档中的开发前置条件包括 Docker Compose v2、mise、配合 Zulu Java 17 的 Maven wrapper、对应源码版本的 Node/pnpm、PM2、curl、timeout 和 OpenSSL。对象存储是必需项，没有本地上传目录回退。

首次环境初始化会将 Submission 切换标记设为 false。应完成迁移、回填、验证和切换运行手册，不能仅将标记设为 true。`dev-lite` 和 `dev-full` 要求远程 Submission 路由与已完成切换标记。`dev-lite` 默认不启动任一前端，需要时请使用前端入口；`dev-full` 包含索引搜索与两个浏览器应用。Core 是可选且范围有限的验证配置，不是默认生产拓扑。

生产环境应保留完整获准的发布描述符与上一份兼容产物。回滚不会降低数据库结构版本。完整恢复覆盖控制 schema、全部五个 Owner schema 和必需对象。存储凭据、加密密钥、保留规则、恢复权限及经过测量的恢复目标由运维方负责。

## 评估协议

1. 约定范围、允许使用的数据、具名发起人与运维人员、评估窗口和成功标准。
2. 使用选定版本及受支持的配置与迁移门禁准备隔离环境。
3. 用已知正确和错误解答，完整执行学习者普通练习提交流程。记录标识及预期和实际最终结果。单独测试管理员权限限制。
4. 演练依赖故障诊断、向一次性目标执行获准的备份与恢复，并测量代表性工作负载。保留队列与恢复证据。
5. 对照约定标准比较结果。决定扩大、重复或停止，并记录评估数据的导出与删除。

通过标准必须覆盖预期身份提供方、无障碍、预期负载、恢复、保留与运营支持。不能用 HTTP 200 或样例截图代替完成这些标准。

## 网站咨询与支持

普通问题可通过登录后的联系表单或公开 GitHub Issue 提交。网站咨询会保存，供站点所有者通过受限 Sites 工具查阅；没有配置或承诺自动邮件转发、工单分配和审阅排班。保存记录不等于预订试点。机构部署出现事件时，请联系自己的运营负责人。

发送者只能列出和删除自己的咨询。记录保留至发送者或所有者删除；独立反滥用计数也没有自动到期机制。网站删除不会清除提供方备份或身份日志。可选分析默认关闭，只保存每日动作计数。不要在普通咨询中提交学生记录、凭据、私有代码、未公开漏洞或敏感日志。

潜在漏洞应通过仓库 GitHub 私密报告渠道提交，不应提交到公开 Issue 或普通咨询。请查看安全页面确认当前可用方式。项目未承诺安全响应时限。
